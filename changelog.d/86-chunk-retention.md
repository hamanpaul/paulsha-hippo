- `ExternalAgentRouter.run_session()`（issue #86，#80 Task 3）不再是全有全無：某 profile 在第 k 個 chunk 失敗時，`0..k-1` 已通過 `_validate_response` 的輸出連同「產出它們的 profile」一併保留，下一個 eligible profile 只從第一個未驗證的 chunk 續跑，frozen prompt 序列與逐一驗證不變。實測案例：3-chunk session 中 profile A 完成 chunk 0、1 後於 chunk 2 失敗，過去 profile B 會收到 `['c0','c1','c2']` 整批重跑；claude 大 session 單 chunk 實測 190–244s，一次失敗即丟掉數百秒已完成的合法產出。新增 `router.chunk_provenance`（每個 chunk 的產出 profile_id／tier／elapsed_seconds），多於一個 profile 貢獻時 session 層 `fallback_reason` 仍為既有的 `degraded-success`；session 級 `AgentRunResult.profile_id` 維持「完成 session 的 profile」，但 slice 的 `distiller` 欄位另外攜帶 `chunk_provenance`，故混合 profile 完成的 session 不會被誤記成單一 profile 產出。`CachingAgentClient.run_session()` 同步改為每個 chunk 驗證通過即落地該 chunk 的 cache envelope（不再等整個 session 成功），envelope 歸屬實際產出該 chunk 的 profile，不同 profile 的同一 chunk 不互相污染；完整 session 的一次性 replay 仍只認單一 profile 全命中，混合 profile 的完整 replay 視為 miss（刻意最小範圍：只要求 per-chunk 落地與隔離，不含混合 replay 最佳化）。`FIXED_TIMEOUT_SECONDS`／`FALLBACK_ON`／`FIXED_MAX_AGENT_CALLS` 不變；session 預算與 agent-call 計數仍跨 profile 連續累計，不因續跑重置；全數耗盡時仍拋 `AgentRunError`、pipeline 仍 park 一次、`attempts_detail` 的 `failure_kind` 分類不變，快取落地不等於發布，parked session 不產生 slice。
