- 新增 entity hub 同步（issue #107）：linker 把 relations ledger 的 `mentions` 邊物化成筆記 frontmatter `related:` 的 `[[EntityName]]` wiki-link，但 entity 從未有對應頁面，連結一寫出來就是斷鏈（2026-08-04 生產盤點：1,464 篇 slices 中 943 篇含斷鏈共 1,408 條、涉及 452 個 entities）；`related:` 每輪重物化、MOC 每輪重生成，修在筆記或 MOC 上都撐不過下一輪 dream cycle，故新增 `moc/entity_hub.py` 維護 knowledge 層 `entities` 子目錄的 hub 頁作為持久解析目標（frontmatter `memory_layer: entity`，census 歸類 `pool:non-knowledge-layer`，linker / moc_builder / index 全部略過、不會被既有 pass 覆蓋）。
- `sync_entity_hubs(memory_root, now, apply=)`：缺頁補 stub（`entity_kind: unclassified`，含反向連結清單）；既有頁只重刷「反向連結」段落——提及 slice 全數消失（prune/dedupe）時刷成 0 篇不留死連結——人工或 agent 補的分類欄位（`entity_kind` / `canonical_moc` / 描述）原樣保留；`alias_of` 頁視為別名，其 mentions 歸戶 canonical 頁反向連結並標註經由變體；含 `#` 的 entity（如 `PR #54`）因 wiki-link 語意中 `#` 是標題錨點（`[[PR #54]]` 解析為頁面 `PR` + 錨點 `54`），於前綴頁維護 `## <錨點>` 段落且**每輪整段重刷**（新 mentions 進場、slice 被 naming.reconcile 改名後不留死 stem），字面檔名頁照建；entity 名與既有筆記檔 stem 相同時跳過；兩個 pass 都只寫自家頁——路徑已存在但非本模組管理的 entity 頁（外來檔、frontmatter 壞損）一律拒寫；路徑組裝剝除 `..`／空成分並套 NAME_MAX byte 上限；`_yaml_quote` 跳脫 `\n`/`\r` 對齊 `frontmatter_io._scalar`（#139），含換行的 entity 名 round-trip 後仍認得自己建的頁。冪等：內容無變化不重寫（不空轉 mtime churn，顧及 vault 同步與 git 備份）。
- 回報兩軌（#101 教訓：每輪必再現的 warning 會讓 dream 永久 partial）：`warnings` 只裝暫時性 I/O 失敗（fail-soft #16，單點失敗不中止整輪、該輪 partial 屬應然）；結構性、無自癒路徑的資料狀態（entity 名組不出合法路徑、外來檔佔位、alias 環）記 `stats["structural"]` 清單與 `skipped_structural` 計數，不進 warnings、不污染 dream 的 clean 判定。
- `run_moc()` 於 build_mocs 後、faceout／index 前接入同步——隨既有 dream 排程（hourly timer）自動執行即為定期維護；回傳新增 `entity_hubs` 計數摘要（剝除 `actions`/`structural` 清單避免落 ledger 膨脹），hub 層壞損以 `entity hub sync degraded` warning 降級、不中止 MOC pass。
- 新增 CLI `hippo knowledge entity-hubs --memory-root … (--dry-run|--apply)`：dry-run（預設）不寫檔、輸出待建/待刷動作與結構性跳過清單，有待辦即 exit 1（比照 `hippo index verify` 的健檢 exit 語意）；apply 出現 I/O 失敗 warnings 亦 exit 1（比照 `rekey`／`prune-noise --paths` 的 apply 錯誤慣例），排程監控不會漏看持續失敗。
