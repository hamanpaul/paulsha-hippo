- 修 issue #141：四個 atomizer 測試（`test_atomizer_e2e.py`、`test_atomizer_cli.py`、`test_atomizer_backend_matrix.py`、`test_atomizer_llm_live.py`）直接呼叫 `paths.atomizer_config_path()` 讀出、原地改寫、蓋回真實 canonical config，沒有 try/finally 還原。`tests/conftest.py` 既有的 autouse fixture `_isolate_runtime_config` 只在 pytest 收集下才生效；用 `python3 -m unittest tests.test_atomizer_e2e...` 這類不經 pytest 的方式跑單一測試（會正確解析到 repo 自己的 `paulsha_hippo` 套件，卻完全跳過 `conftest.py`）時，`paths.atomizer_config_path()` 直接落回使用者真實的 `~/.config/paulsha-hippo/config.yaml`。生產實證：2026-08-25 這條路徑把使用者真實 config 蓋成單一 `fake-agent` profile，31 筆 session 被 parked，知識蒸餾靜默停擺一週。
- 新增 `tests/atomizer_config_testutil.py::isolated_atomizer_config()`：context manager，在 `with` 區塊內把 `HIPPO_CONFIG_ROOT` 覆寫指到每次呼叫各自新建的 tmp dir（已用 shipped `atomizer.yaml` 模板 seed），並在區塊結束（含例外）時還原環境變數。四個 culprit 測試檔改用這個共用 helper 包住「讀寫 canonical config ＋呼叫 `cli.main`/`_atomize`」的整段區塊，不再仰賴僅在 pytest 下才生效的 ambient fixture；即使被跳過 pytest 直接執行，isolation 依然成立。`tests/test_dream_supervise_e2e.py` 稽核後確認本來就是先隔離整個 `HOME` 再手動組路徑寫入，從未呼叫 `paths.atomizer_config_path()`，不是本次汙染的成因，未變動。
- `tests/conftest.py` 新增 regression guard `_guard_real_hippo_config_untouched`（session-scoped autouse）：在整個 pytest session 開始／結束時，直接以 `Path.home()` 計算（刻意忽略任何 `HIPPO_CONFIG_ROOT`／`PSC_CONFIG_ROOT` override）比對使用者真實 `~/.config/paulsha-hippo/config.yaml` 的 bytes 是否有變化，一旦變化就讓整個 test run 失敗並指名是這一類回歸。
- 新增 `tests/test_atomizer_config_testutil.py`：驗證 `isolated_atomizer_config()` 產出的路徑確實落在 tmp dir（而非真實 home 路徑）、且無論區塊正常結束或拋例外都會還原 `HIPPO_CONFIG_ROOT`。
- 已知限制（本次不修）：在 `tests/` 目錄內以「裸執行腳本」方式（例如 `cd tests && python3 test_x.py`）啟動測試時，`paulsha_hippo` 會解析到使用者機器上一份較舊的 `pip install` 產物（`~/.local/lib/python3.12/site-packages/paulsha_hippo/`）而非 repo 原始碼——這是既有、與本次修復無關的本機環境問題（並非 editable install），任何測試檔案（含本次新增／未動到的檔案）以該方式執行皆會受影響；本 PR 的修復與其 regression guard 在 `pytest`（`.project-policy.yml` 宣告的 preflight 步驟）與 `python3 -m unittest tests.<module>`（repo root 為 cwd，即事故的精確重現方式）下皆已驗證正確。
