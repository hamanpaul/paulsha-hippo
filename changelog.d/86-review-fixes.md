- `paulsha_hippo/atomizer/agent_exec.py` `CachingAgentClient.run_session()`（#86 review BLOCKING）：先前只在 `self._inner.run_session()` 整個 session 成功回傳後才落地每個 chunk 的 cache envelope；一旦該次呼叫最終仍全數耗盡（`AgentRunError`），已驗證前綴一律不落地，與 changelog／design doc 宣稱的「每個 chunk 驗證通過即落地、不再等整個 session 成功」矛盾，`run_session()` 自身舊 docstring（「without persisting partial chunks」）反而更貼近實際行為。實測：2-profile、2-chunk 情境，`first` 驗證通過 chunk-0 後兩個 profile 都在 chunk-1 失敗，修復前 `tmp_path` 下 cache 檔案數為 0。`ExternalAgentRouter.run_session()` 新增 keyword-only `on_chunk_validated` callback，於每個 chunk 通過 `_validate_response` 的當下同步觸發（成功或最終耗盡皆會先觸發到已驗證的 chunk 才可能失敗）；`CachingAgentClient` 傳入此 callback 立即落地該 chunk 的 envelope，不再等待整個 session 的回傳值。耗盡語意不變：`AgentRunError` 仍原樣拋出、pipeline 仍 park、`attempts_detail` 分類不變、快取落地不等於發布，parked session 依舊不產生 slice。`run_session()` docstring 同步更正以反映實際行為。新增 `tests/test_external_agent_profiles.py::test_session_cache_lands_validated_chunk_even_when_session_later_exhausts` 驗證耗盡情境下已驗證的 chunk-0 仍落地、未驗證的 chunk-1 不落地。
